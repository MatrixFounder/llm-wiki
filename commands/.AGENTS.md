# commands/ — source of truth for the project's `wiki-*` slash commands

Small wrapper files (3–6 lines) that Claude Code runs as `/<name>`. Each either points at a
workflow in `workflows/` or directly describes what to do.

## Template

```markdown
Read and execute the workflow defined in `workflows/<workflow-name>.md`.

Follow all steps sequentially. Load required skills as specified in each step.

User's task context:
$ARGUMENTS
```

The current set is **18 `wiki-*` commands** (one per CLI; `wiki-import` + the back-compat alias
`wiki-import-article`). The names must match `bin/wiki-*` and `skills/wiki-*/`.

## Wiring into Claude Code (two levels)

- **In-repo** (`.claude/commands/<name>.md` → `../../commands/<name>.md`): created in bulk by
  `bin/install-project-symlinks.sh` (or one at a time with `bin/link-command.sh <name>`).
- **Global** (`~/.claude/commands/<name>.md` — so `/wiki-*` work from any project):
  `bin/install-globally.sh`. Both scripts are **idempotent and safe** (create what's missing,
  repair their own symlinks, **never clobber foreign ones**, and print a per-item report).

> **Added a new command?** Re-run the relevant install script — new files are NOT picked up
> automatically (that's exactly why `/wiki-import` was invisible for a while).

Legacy commands (`.claude/commands/vdd*.md`, `start-feature.md`, etc.) are plain files — leave
them alone (the install scripts skip them as "foreign").
