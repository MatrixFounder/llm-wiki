# config/ — Configuration Artifacts Memory

**Owner**: schema files consumed by the three (independent) config systems —
`scripts/wiki_index/config_loader.py` (per-vault identity), `…/layout_config.py`
(per-layout grammar), and `…/sync_config.py` (the `wiki-sync` dispatcher,
TASK 018). Edits go through the Schema Change Request workflow — see
`sql/.AGENTS.md` precedent.

## Files

- `wiki-config.schema.yaml` — JSON Schema 2020-12 for the `wiki:` block in
  CLAUDE.md (root) and `.wiki.yaml` (project override). **TASK 012**: its
  `layout` enum widened to the 5 `--layout` values (`flat`/`per-project`/
  `karpathy`/`dev-project`/`obsidian-personal`); `flat`/`per-project` are
  **back-compat aliases → karpathy**. **TASK 022**: added optional
  `index_db: {type: string}` to `WikiRootConfig` (vault-local DB declaration, DiD — the

- `layout-config.schema.yaml` — **TASK 012 / R-X1**: JSON Schema 2020-12 for the
  **per-layout-class parsing grammar** consumed by
  `scripts/wiki_index/layout_config.py` (the NEW second config system — NOT the
  per-vault identity above). Validates a `LayoutConfig`: `paths[]` (glob /
  `project_pattern`+`project_template` / `slug_strategy` / `type`/`extra_tags`),
  `type_mapping`, `path_type_fallback`, `ref_extraction[]` (regex rules,
  ReDoS-budget-gated at load), `slug_strategy`, `ignore[]`, `file_extensions`,
  `frontmatter_synthesis`, `auto_indexes[]` (output ledger). **TASK 036 / R-15**:
  optional `drift_rules[]` / `coverage_rules[]` (`$defs DriftRule`/`CoverageRule`) —
  the derived-knowledge-health rules. **TASK 054 / R-19**: optional `ontology` object
  (`$defs Ontology`/`OntologyEdge`/`OntologyProperty`: `closed_types` + `edges`
  domain/range + `properties` value-enums) — the formal type/edge/property contract.
  All three are cybos-only + semantically re-validated in Python at load
  (`_validate_health_rules` / `_validate_ontology`; typo → exit 6). **Strict**:
  `additionalProperties:false` at PathEntry/AutoIndex/Ontology level so a misspelled key →
  exit-6. The built-in layouts live next to the engine at
  `scripts/wiki_index/layouts/{karpathy,dev-project,obsidian-personal,cybos}.yaml`
  (karpathy.yaml is a validated projection of `layout.py` — byte-identity anchor).
- `sync-config.schema.yaml` — **TASK 018 / R-11**: JSON Schema 2020-12 for the
  per-vault **`.wiki/sync.yaml`** consumed by `scripts/wiki_index/sync_config.py`
  (the THIRD config system — the `wiki-sync` format-aware, tag-routed ingest
  dispatcher; distinct from identity + layout-grammar above). Validates `zones`,
  `exclude`, `tag_namespace` (default `wiki`), `extensions` (`convert`/`text`/
  `skip` overrides). **TASK 019** added the opt-in `$def Resummarize` (`Detect` =
  `source_state` ∪ `ProvenanceRef` ∪ `Mirror{group_key,key{raw,summary,template,flags}}`)
  for the re-summarization gate, per-folder overridable via `<dir>/.wiki/sync.yaml`.
  **TASK 021** notes on `Mirror`: `group_key` default `^(\d+)` + leading-zero normalisation
  define a leading-zero-INSENSITIVE numeric equivalence class (use a delimited/`template`
  key for multi-component lessons); `summary_ext` is single-valued (the mirror sees one
  extension). **Strict** (`additionalProperties:false` everywhere) → a
  misspelled key is `INVALID_SYNC_CONFIG` (exit 6). The file is OPTIONAL (absent →
  built-in defaults). The loader hardens an untrusted file beyond the schema:
  full-path symlink containment + a 256 KiB size cap + a `SafeLoader` that refuses
  YAML anchors/aliases + `RecursionError`-safe (SEC-N3) — see `security.md §7.5`.
  **TASK 058** adds ADDITIVE `x-wiki-*` annotations (unknown keywords — instance
  validation is byte-unchanged): `x-wiki-scope: root-only|cascading` on the 7

## Round-trip invariants

The `VaultId` pattern in this schema **MUST match** the SQLite CHECK
constraint in `sql/wiki-index-v2.sql::vaults.vault_id` byte-for-byte. Any
divergence creates a class of bugs where YAML-validated config gets rejected by
SQLite (or vice versa) — both layers must agree.

Current spec (ADR-002 §D1.1 + architecture-review M-1):
- Pattern: `^[a-z][a-z0-9-]{1,30}[a-z0-9]$`
- No double hyphens (negated subpattern: `--`)
- Length 3–32
- `_global_` sentinel allowed (M-7)

## When tightening (task-001-13)

The Phase 3a stub uses `additionalProperties: true` for forward-compat.
task-001-13 will tighten by:
1. Setting `additionalProperties: false` on confirmed-stable definitions.
2. Removing the `transcript` / `light_summary` defs entirely (Phase 3b
   reintroduces them with the wiki-ingest wrapper).
3. Adding `wiki-ingest` config sub-block (post-v1.1 release).

> **N.B. (TASK 047):** items 2–3 are moot — the `wiki-ingest` wrapper and its vendored
> module were retired; the converged `wiki-import` engine (TASK 046) is the construct path now.
