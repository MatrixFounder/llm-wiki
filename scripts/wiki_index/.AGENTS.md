# scripts/wiki_index/ — DAL Module Memory

**Purpose**: Data Access Layer for the multi-vault SQLite index. All read/write
to the DB goes through `IndexRepository` (abstract) and `SQLiteRepository`
(concrete). Skills never construct raw SQL — they call repository methods.

  **TASK 030 (R-030-2a)**: the DML bodies of `upsert_page`/`replace_refs` are
  factored into PRIVATE txn-free helpers `_upsert_page_in_txn(conn, page, *,
  skip_unchanged_check=False)` / `_replace_refs_in_txn(conn, …)` — **the caller
  MUST hold an open transaction**, no exceptions (a bare autocommit call makes
  the refs DELETE and each INSERT row SEPARATE implicit transactions — a crash
  mid-call destroys the page's refs with no rollback); they issue no
  BEGIN/COMMIT/ROLLBACK and are NOT on the `IndexRepository` ABC. The public
  methods keep their own-tx semantics by delegating (M-4 untouched; a public
  call inside a foreign open tx still raises `OperationalError` — pinned by
  `tests/test_task030_dal_helpers.py`). `skip_unchanged_check=True` = the
  full-rebuild path (F-6): hash pre-SELECT skipped, outcome nominal, within-
  batch PK conflicts resolve via ON CONFLICT (last file wins — Q-030-5).
  Consumers: the public wrappers + `reindex_full`'s chunked flush (below).
  **TASK 030 (R-030-2b, closes P-1)**: `reindex_full` Step 2 is **stage-then-
  flush**: derivation (ALL file I/O) stages OUTSIDE any txn into a buffer
  bounded by `REINDEX_TX_CHUNK`=500 pages ∧ `REINDEX_TX_CHUNK_BYTES`=32 MiB
  (full-body pages, TASK 024); each chunk flushes page+refs+entity+alias DML
  under ONE `BEGIN IMMEDIATE` (write lock held ms-scale — Q-030-5/HIGH-2:
  never across file I/O; concurrent writers on a shared global.db stay live).
  Per-page commits ~2N → ceil(N/K)+1 (the wipe; `_recompute_mentions`/
  `append_log_event`/batch bookkeeping ride autocommit — pinned by the AC-2.4
  trace test). The flush path uses `_upsert_page_in_txn(skip_unchanged_check=
  True)` — post-wipe the pre-SELECT is dead weight; in the equal-hash within-
  batch collision corner this ALIGNS the DB `file_path` with the
  `slug_collisions.kept` record (deliberate delta, AC-2.6). Error semantics:
  staging errors = zero DML; mid-flush DML errors = statement-atomic,
  committed-with-chunk + `skipped`; COMMIT/BEGIN failure = fatal → chunk
  ROLLBACK + batch "failed" (FTS triggers ride the tx — no desync).

## Class A/B/C discipline (ADR-002 §D8)

This module owns the DB-side cache. Everything it writes is Class B (rebuildable
from markdown) except `vaults.registered_at` (Class C strict — approximated on
reindex). When adding a new column or table:

1. Classify it (A/B/C). If unsure, default to B and document the rebuild path.
2. If Class A — DO NOT add to schema. Belongs in vault markdown only.
3. If Class C — minimize. Justify why view/computed value won't work.

## Upsert contract (M-4)

`pages` and `entities` upserts MUST use
`INSERT … ON CONFLICT(<composite>) DO UPDATE SET …`. **NEVER**
`INSERT OR REPLACE` — see `sql/.AGENTS.md`. The repository must enforce this
at the SQL-string level (grep-test in CI: no `INSERT OR REPLACE` strings in
this directory).
