# scripts/wiki_index/ — DAL Module Memory

**Purpose**: Data Access Layer for the multi-vault SQLite index. All read/write
to the DB goes through `IndexRepository` (abstract) and `SQLiteRepository`
(concrete). Skills never construct raw SQL — they call repository methods.

## Class A/B/C discipline (ADR-002 §D8)

This module owns the DB-side cache. Everything it writes is Class B (rebuildable
from markdown) except `vaults.registered_at` (Class C strict — approximated on
reindex). When adding a new column or table:

1. Classify it (A/B/C). If unsure, default to B and document the rebuild path.
2. If Class A — DO NOT add to schema. Belongs in vault markdown only.
3. If Class C — minimize. Justify why view/computed value won't work.

## Upsert contract (M-4)

`pages` and `entities` upserts MUST use
`INSERT … ON CONFLICT(<composite>) DO UPDATE SET …`. **NEVER**
`INSERT OR REPLACE` — see `sql/.AGENTS.md`. The repository must enforce this
at the SQL-string level (grep-test in CI: no `INSERT OR REPLACE` strings in
this directory).
