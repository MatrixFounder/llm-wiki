# scripts/wiki_skills/ — CLI Skill Scaffolds

User-facing entry points. Each module is invokable as
`python -m scripts.wiki_skills.<name> ...`. All modules now ship real impls
(Phase 3a complete).

## Files

- `wiki_init.py` — UC-01; modes: `--scaffold-new` / `--register-existing` /
  `--reconcile`. Threads its own `_emit` with per-error `exit_code`. **TASK 012 /
  R-X2-A**: `--layout` flag (`_LAYOUT_CHOICES` = the 5 values; default `karpathy`)
  writes `layout: <name>` into the scaffolded `WIKI_SCHEMA.md`. Only the
  `_KARPATHY_LAYOUTS` set (`flat`/`per-project`/`karpathy`) scaffolds the Karpathy
  dir tree; `dev-project`/`obsidian-personal` skip it (their files already exist /
  use their own shape). Resolves the named built-in via `layout_config`.
- `wiki_search.py` — UC-03 FTS5 search. Cross-vault via `--vaults` (or
  `_global_` sentinel for "all"). **TASK 013 (R-X3-META-FILTER)**: frontmatter
  **metadata filter** — `--where 'field=value'` (repeatable, AND) + `--status`/
  `--severity` sugar (desugar into `where_fields`). `_parse_where` splits on the
  first `=`, strips, and allow-list-validates the field via
  `repository.validate_filter_field` (the value is never validated — it becomes a
  bound param). The positional `query` is now `nargs='?'`: omit it for a **pure
  metadata listing** (non-FTS path — skips alias-expansion + the DF-1 FTS-quote
  fallback). Bad field / malformed `--where` → `INVALID_FILTER` (exit 2) that
  **never echoes the value** (CWE-209/117); neither query nor filter → `INVALID_QUERY`.
- `wiki_lint.py` — UC-04 SQL-level lint. Optional `--report` md /
  `--json-sidecar` outputs.
- `wiki_index_render.py` — UC-05 `index.md` projection. Preserves
  `<!-- BEGIN-CUSTOM:name -->` blocks across renders. **TASK 012 / PW-H**:
  `--auto-indexes` flag re-renders the layout's `auto_indexes[]` outputs (e.g.
  `docs/KNOWN_ISSUES.md` from `docs/issues/*.md`) via
  `rendering.render_and_write_auto_indexes` — the Class-B rebuildable ledger.
- `wiki_append_log.py` — bi-directional log.md ↔ log_events sync. Emits
  `LOG_APPEND_FAILED` envelope on write failure (rolls back log_events row).
- `wiki_index_upsert.py` — single-file ingest. Stub-compatible `unchanged`
  return when file_hash unchanged.
- `wiki_reindex.py` — `--full` / `--delta` / `--all-vaults` modes.
- `wiki_confirm.py` — **TASK 005 / R-4.2/4.3/4.4** (Epic 7 entity resolver).
  Promote candidate→confirmed (`--undo` demotes; `--auto --threshold N`
  bulk-promotes by mentions, default 3; `--dry-run`). Class A frontmatter
  (`is_candidate`) written FIRST, then `repo.set_entity_candidate` (bypasses the
  re-extraction MIN() guard). Exit 0/2/3/4. The optional `promote`/`demote`
  log_events row (Q5) is deferred (needs log.md M-2 mirroring).
- `wiki_alias.py` — **TASK 005 / R-5.1/5.2**. `--add`/`--remove`/`--list` alias
  surfaces; Class A `aliases:` frontmatter + `entity_aliases` mirror. Collision
  → `ALIAS_COLLISION` (exit 5, names the conflicting slug, never the surface).
- `wiki_merge.py` — **TASK 005 / R-4.7**. Fold duplicate `from`→`into`: Class A
  first (append `into.aliases` + delete `from` page) then `repo.merge_entities`.
  Alias table is the durable redirect (C-7, no wikilink rewriting). Exit
  0/2/3/4/5(`INVALID_MERGE`)/6(`MERGE_MIRROR_FAILED`).
- `wiki_search.py` / `wiki_lint.py` — **TASK 005 extensions**: search expands
  queries through aliases by default (`--no-expand-aliases` opt-out, R-5.5);
  lint adds an `alias-collision` category (DB + Class A frontmatter scan, R-5.6;
  `--strict` → non-zero advisory exit).
- `_common.py` — shared CLI helpers: `emit` (JSON envelope), `atomic_write_text`
  (tempfile+fsync+`os.replace`), `resolve_entity_file` (entity `file_path` →
  validated absolute path via `get_entity_file_path` + `validate_inside_vault`),
  and `sanitize_markdown_text` (text-only allowlist egress guard — **TASK 007**
  lifted it here from `wiki_extract_concepts` per Decision-16 so that skill and
  `wiki_query` share one implementation).
- `wiki_query.py` — **TASK 007 / R-6** RAG over FTS5 + entity graph. Two-pass
  Decision-17 skill (no `import anthropic`): `prepare` (alias-expanded retrieval
  → context envelope; `NO_CONTEXT` below `--min-hits`; default-excludes
  `type=query` so a RAG answer grounds on primary sources + re-query stays
  idempotent) and `apply` (re-retrieve + `question_hash` TOCTOU → `QUESTION_CHANGED`;
  grounding gate `CITATION_NOT_RETRIEVED` keyed on `project/slug`; sanitise +
  atomic-write Class A `_queries/<slug>.md`; self-index via **direct**
  `upsert_page`+`replace_refs` (NOT the manifest N+1) + `record_query_state` +
  a `query` log event). `apply` mirrors `prepare`'s retrieval-scope flags to
  reproduce the hash.
- `wiki_verify_multi.py` — **TASK 008 / R-8** off-by-default multi-critic
  verification of a filed `wiki-query` answer. Two-pass Decision-17 skill (no
  `import anthropic`): `prepare <query-slug>` (load the query page + cited source
  bodies via **`pages.file_path`** — layout-agnostic, grep-guarded, no
  PAGE_SUBDIRS literal; `NO_SOURCES` on empty `cites:`; emits the verification
  envelope; `verification_slug` defaults to **`verify-<query-slug>`** — distinct
  `pages` PK so the verdict page does NOT overwrite the query page) and `apply`
  (re-read query page + `answer_hash` TOCTOU → `ANSWER_CHANGED`; grounding gate
  `FINDING_SOURCE_NOT_EXAMINED` keyed on `project/slug`; **Python-derived**
  PASS/FAIL via `--fail-on` (default `high`, overrides the LLM's self-report);
  sanitise + atomic-write Class A `_verifications/verify-<slug>.md`; self-index
  via **direct** `upsert_page`+`replace_refs(verifies[+cited])` (NOT the manifest
  N+1) + `record_verify_state` + a `verify` log event). **FAIL → exit 6** (a
  SUCCESS envelope, no `error` key — deliberate divergence from the family's
  `6=error`; callers branch on the stdout `verdict`). **The Class-A answer is
  NEVER mutated** (D-008-3).
- `_retrieval.py` — **TASK 007 / C-6** shared FTS retrieval (`expand_query` +
  `fts_quote`) extracted from `wiki_search`; imported by both `wiki_search` and
  `wiki_query` so the alias-expanded retrieval lives in one place (wiki-search
  output byte-identical).
- `wiki_enrich.py` — bridge to `wiki-ingest` (ADR-001 Option I). Post-TASK
  004 (2026-05-27): **two-path design**. PRIMARY = in-process call into
  vendored `scripts.wiki_ingest.commands.ingest.ingest()` — no subprocess,
  no PATH dependency. FALLBACK = legacy subprocess via `wiki-ingest` CLI
  on PATH. Decision: `_VENDORED_AVAILABLE and not _force_subprocess`,
  where `_force_subprocess` reads `WIKI_ENRICH_NO_VENDORED` env-var
  (case-insensitive truthy set `{1, true, yes, on}`, whitespace-stripped
  — per `/vdd-multi` 2026-05-27 H-3 hardening). If vendored import fails
  AND `wiki-ingest` not on PATH → exit 6 with `{"error":
  "WIKI_INGEST_UNAVAILABLE"}`. `IngestError` from the vendored path is
  content-level — does NOT fall back to subprocess. **Post-TASK 003 v2
  (Decision-16)**: `validate_manifest`, `index_from_manifest`, and
  `WikiIngestError` no longer live in this file — moved to
  `_manifest_consumer.py`. This module re-exports the three symbols
  (back-compat alias `_validate_manifest = validate_manifest` kept one
  release cycle for existing test imports). `index_from_manifest` (now
  in `_manifest_consumer.py`) applies (a) R-0 top-level-system-file
  skip + (b) `/vdd-multi` absolute-path-rejection guard + (c) narrow
  exception catch `(OSError, ValueError, KeyError, RuntimeError)`.
- `_manifest_consumer.py` — **neutral sub-layer module** (TASK 003 v2 /
  Decision-16 / I-7.0). Holds `validate_manifest`, `index_from_manifest`,
  `WikiIngestError`. Neither this module nor its consumers belong to a
  specific skill; placing them here breaks the "no skill imports from
  another skill" coupling that Decision-15's first draft would have
  introduced. Import-time neutral; `index_from_manifest` still reaches
  into `wiki_index_upsert` via a lazy in-function import for
  circular-dep safety. Both `wiki_enrich.py` and `wiki_extract_concepts.py`
  import from this module.
- `wiki_extract_concepts.py` — **TASK 003 v3.1 entry-point** (Epic 7 R-3,
  shipped 2026-05-28 commit `43812f2`; supersedes v2). Decision-17:
  deterministic two-subcommand surface (`prepare` + `apply`); the LLM
  call lives in the **calling agent's** context, not this module — see
  `skills/concept-extraction/SKILL.md` for the synthesis contract.
  - `prepare(args)` — argparse handler for `prepare` subcommand.
    Resolves source-page via `_resolve_source_inside_sources` (H-1
    `_sources/` layout invariant — rejects `_sources/../_concepts/foo.md`
    traversal); reads body via `_read_file_bounded(path, 10 MiB)`
    (M-3+M-5: `os.open(O_NOFOLLOW)` + `os.fstat` + bounded `os.read`);
    computes sha256; calls `check_idempotency` + `load_known_entities`;
    sweeps `missing_concept_files` via single `os.scandir` (M-7);
    emits JSON envelope with **relative** `source_path` (M-2 closes
    CWE-209 absolute-path disclosure).
  - `apply(args)` — argparse handler for `apply` subcommand. Loads
    candidates via `_load_candidates` (stdin bounded to cap+1 bytes;
    file path validated inside vault + rejected if non-regular
    (H-2 FIFO/device/socket guard) + read via `os.open(O_NOFOLLOW)` +
    bounded read); resolves + reads source identically to prepare;
    hash-checks `--source-hash` (validated as 64-lowercase-hex by
    argparse `type=_validate_source_hash` per C-1; library-caller
    defense emits `INVALID_SOURCE_HASH` envelope); validates schema
    via `_validate_candidates_schema`; runs `_preflight_sanitize` (M-4:
    dry-pass sanitizers BEFORE any write so a mid-loop failure can't
    leave partial pages); classifies create/mention; writes pages +
    upserts entities + refs + manifest; optionally dispatches via
    `_manifest_consumer.index_from_manifest`; `_try_update_idempotency_state`
    (H-3: `sqlite3.OperationalError`-aware) emits new
    `IDEMPOTENCY_UPDATE_FAILED` envelope at exit 5 instead of uncaught
    traceback.
  - `write_concept_page` — atomic tempfile + `os.replace`; symlink-refuse
    on target (Q15); content-hash skip via `os.open(O_NOFOLLOW)` for
    the existing-file read (M-5 closes symlink-follow disclosure);
    body construction uses `_sanitize_name` (regex allowlist) +
    `_sanitize_definition` + `_format_source_quote_block` (both
    delegate to `_sanitize_markdown_text` text-only allowlist — H-4
    replaces v3.0 denylist; escapes `&<>` + backticks + `[]` +
    leading-line markdown actives).
  - Helpers: `_validate_candidates_schema` (strict equality on keys +
    per-field caps + count bound + L-1 type-coverage on
    slug/source_span/entity_type + defensive isinstance guard);
    `_validate_source_hash` (C-1 argparse `type=`);
    `_validate_orchestrator_id` (H-8); `_path_is_absolute` (M-6
    cross-platform: catches `/etc/passwd` on Windows + `C:\foo` on
    POSIX); span regexes compiled with `re.ASCII` (L-2 — rejects
    Unicode digits); `_envelope_from_parse_error` builds CWE-117
    envelopes from `ExtractionParseError` structured attrs
    (`.error`/`.field`/`.reason`, NEVER `.value`/`.raw`).
  - Module-top imports of `validate_manifest`, `index_from_manifest`,
    `WikiIngestError` from `_manifest_consumer` lock `mock.patch`
    targets at `scripts.wiki_skills.wiki_extract_concepts.<symbol>`
    (PLAN.md Risk R-1, carried forward from v2).
  - **No `anthropic` import. No `ANTHROPIC_API_KEY`. No LLM call.**
  - Exit codes: 0 (success) / 1 (argparse) / 2 (`SOURCE_NOT_FOUND` |
    `INVALID_SOURCE_PATH` | `INVALID_SOURCE_SLUG` | `SOURCE_TOO_LARGE` |
    `SOURCE_CHANGED_DURING_EXTRACTION` | `INVALID_SOURCE_HASH` |
    `INVALID_CANDIDATES_PATH`) / 4 (`EXTRACTION_PARSE_ERROR` |
    `CANDIDATES_TOO_LARGE` | `CANDIDATE_COUNT_OUT_OF_BOUNDS` |
    `FIELD_TOO_LONG` | `UNKNOWN_FIELD` | `FIELD_QUOTE_NOT_IN_BODY` |
    `INVALID_SOURCE_SPAN`) / 5 (`PARTIAL_INDEX_FAILURE` |
    `IDEMPOTENCY_UPDATE_FAILED` — both preserve C-1 retry-safety) /
    6 (`MANIFEST_INVALID`). The v2 exit-3 `LLM_API_UNAVAILABLE` is
    retired.
  - **BREAKING CHANGE** vs v2: the monolithic `wiki-extract-concepts
    --vault X --source-page Y` (no subcommand) is rejected at
    argparse with a helpful pointer at `{prepare,apply}`.
- `_common.py` — `emit(payload, exit_code=0)` helper. **Error envelopes
  MUST pass `exit_code=6`** (convention from `wiki_init._emit`) so shell
  scripts and tests detect failure via `$?`.

## Contract

- Each module exposes `def main(argv: list[str] | None = None) -> int` for
  programmatic invocation by tests and the E2E harness.
- All output is JSON to stdout, one line; exit code 0 = success, 6 =
  validation/lookup error, 7 = interactive-confirm-required warning.
- CLI without a specific `--vault` (search/lint/reindex) passes the
  `_global_` sentinel (from `scripts/wiki_index/layout.py`) to the factory
  instead of inventing a fake vault_id.
