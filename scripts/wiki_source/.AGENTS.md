# scripts/wiki_source/ — Source Adapters Module Memory

**Purpose**: Pluggable adapters that normalize different source kinds (manual
markdown, transcript via wiki-ingest workflow, light LLM summary) into
`SourceOutput` dataclasses that `wiki-index-upsert` consumes.

## Files (planned for Phase 3a)

- `adapter.py` — `SourceAdapter` ABC + dataclasses (`SourceItem`,
  `SourceOutput`). (task-001-06)
- `manual.py` — `wiki-source-manual` adapter: indexes existing markdown files
  produced by wiki-ingest. Sets `trust_level='high'`. Path-traversal guarded
  (R-26). (task-001-07 stub → task-001-24 impl)
- `parsing.py` — markdown parsing helpers (frontmatter, refs, slugs). **TASK 012 /
  R-X1 (PW-D/F/L)**: `extract_refs(body, rules)` runs the layout's
  `ref_extraction[]` regex rules (wiki-links, markdown links, id-refs) — config-driven;
  the legacy `extract_wiki_links`/`_WIKILINK_RE` are kept untouched as the karpathy
  byte-identity path. **TASK 017 / R-X1-REDOS-RT**: `extract_refs(..., operator_supplied,
  budget_s)` — built-in rules pre-compile once under stdlib `re` (hot path); operator-custom
  rules run via `layout_config.guarded_finditer` under the `regex` engine with a per-file
  wall-clock deadline → `TimeoutError` ⇒ skip-file-refs + WARN (empty, never hangs/raises). `first_h1` (H1-title synthesis source). `derive_slug` now routes
  through `_apply_slug_strategy` (`identity` [karpathy — verbatim stem, no slugify] /
  `preserve-unicode` / `transliterate` / `ascii-only`). The concept-tag `_slugify_concept`
  strict slug surface is **deliberately NOT** routed here (kept distinct — see
  `wiki_index/.AGENTS.md` three-slug-surfaces note).

## Out of Phase 3a (Phase 3b — wait for wiki-ingest v1.1)

  R-06.3. Subprocess + JSON manifest consumption.
