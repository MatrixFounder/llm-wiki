# skills/ — source of truth для wiki-* скиллов

Сюда кладутся новые скиллы проекта (`wiki-init`, `wiki-update-index`, `wiki-append-log`, `wiki-search`, `wiki-extract-concepts`, `wiki-lint`, `wiki-query`, `concept-extraction`, и т. д.). Структура каждого — стандартная (`SKILL.md`, опц. `scripts/`, `references/`, `assets/`).

`concept-extraction` (TASK 003 v3.1, 2026-05-28) — operator-facing
extraction-prompt skill loaded by the orchestrator BETWEEN
`wiki-extract-concepts prepare` and `wiki-extract-concepts apply` (UC-08
v3.1 Step 4). Pure prompt + JSON-candidates contract; no scripts. Carries
H-5 integrity advisory + H-6 indirect-prompt-injection mitigation
banner (see `docs/KNOWN_ISSUES.md`). SECURITY-SENSITIVE: any PR
touching `skills/concept-extraction/` MUST receive a SECURITY label.

`wiki-query-synthesis` (TASK 007, 2026-05-29) — the analogous operator-facing
prompt skill for the RAG layer, loaded by the orchestrator BETWEEN
`wiki-query prepare` and `wiki-query apply`. Defines the cited-answer +
citations-JSON contract + the grounding rule (cite only retrieved hits) + the
H-6 untrusted-retrieved-content prompt-armor. Pure prompt; no scripts.
**SECURITY-SENSITIVE** (loaded into LLM context at runtime — same banner +
SECURITY-label rule as `concept-extraction`). The deterministic CLI half is
`skills/wiki-query/` (subcommand reference, synced with the `wiki_query.py`
argparse).

`wiki-verify` (TASK 008, 2026-05-29) — the operator-facing four-critic prompt
skill for the RAG **verification** layer (R-8), loaded by the orchestrator
BETWEEN `wiki-verify-multi prepare` and `apply`. Defines the four prose lenses
(factual-grounding / logic-coherence / security-injection / completeness-
faithfulness) + the verdict-JSON contract + the grounding rule (every finding
source ∈ examined set) + the H-6 untrusted answer+source prompt-armor. Pure
prompt; no scripts. **SECURITY-SENSITIVE** (loaded into LLM context at runtime —
same banner + SECURITY-label rule as `concept-extraction` / `wiki-query-synthesis`).
The deterministic CLI half is `skills/wiki-verify-multi/` (subcommand + exit-code
reference, synced with the `wiki_verify_multi.py` argparse).

`wiki-verify` **R-9 hardening (TASK 009, 2026-05-29)** — the four lenses are now
**scoped** (exclusive domains — anti-bleed), **severity-calibrated** (one shared rubric),
and **few-shot-backed**, with the **C2 backstop** (`factual`+`security` are the only
sanctioned injection overlap; `logic`/`completeness` MUST NOT re-report injections). A
durable **committed eval set + deterministic grader** live at `skills/wiki-verify/evals/`
(`evals.json` 7 cases, `grade.py` — which *calls* the shipped `_is_fail` so the eval can't
drift from the gate, `README.md`). The baseline→enriched measurement is
**orchestrator-graded** (`workflows/wiki-verify-eval.md` fans the critics out; scoring is
deterministic) and recorded under `evals/reports/{baseline,enriched,delta}.md` — it is
**NOT** a `pytest` gate (a live LLM judge can't be pinned in CI). The deterministic CI pins
are `tests/test_wiki_verify_{evals,grade,skill_contract}.py`. Any few-shot example attack
string is fenced/inline-coded (the **defang control**, enforced by the contract test).
**Zero shipped-code/schema change** (`user_version` 5; `wiki_verify_multi.py` untouched).

banner + SECURITY-label rule as `concept-extraction`/`wiki-query-synthesis`/`wiki-verify`, and
since **TASK 067 / H-5** actually HASH-PINNED in `config/skill-integrity.sha256` — the marker was
added and the pin made real after the H-5 adversarial review found it designated-but-unpinned;
re-pin an approved edit with `python3 scripts/pin_skill_integrity.py --write`):
it carries a TOTAL T1/T2/T3 tier function (`eval`/`dev:*`/plugin-snippet-theme mutations
T3-banned-by-default, NEVER from note content; `command id=`+`template:insert` active-file
default-DENY; **Templater/QuickAdd template application inherits T3** unless `template:read`-
verified JS-free) + a mutation→index coherence protocol (`wiki-index-upsert` after a content
edit; **`wiki-reindex --full` after a rename/move** — DF-029-1). **v1.0 was pure prompt +
committed eval assets, zero DDL.** **TASK 041 / ADR-008 (v1.1)** adds **Active-note resolution**
(pathless "edit the note" → confidence-gated resolution of the active/open tab; amends the
F-4 footgun rule) backed by ONE stdlib skill-local helper
`scripts/obsidian_active_note.py` (entrypoint `bin/obsidian-active-note`; no `import anthropic`,

fixtures under `evals/fixtures/`). Shipped via the full VDD pipeline + per-bead
Sarcasmotron + a 4-gate parallel final pass + a live dogfood (found+fixed DF-029-1). See
`docs/tasks/task-029-*.md`, `docs/reviews/task-029-final-gates-review.md`, ARCHITECTURE §2.2/§2.2.1.
**TASK 068 (v1.2, 2026-07-15)** adds the **editor-selection bridge**: READ or safely EDIT the
*live editor selection* from the shell. Two artifacts: a least-privilege Obsidian plugin
`plugin/agent-bridge/` (`main.ts` + hand-authored CommonJS `main.js` + vendored `obsidian.d.ts`;
two plain-`callback` commands `export-selection`/`apply-edit`, all I/O via `app.vault.adapter`, no
`require('fs')`/`child_process`/network) dispatched by the **T2** `command id=agent-bridge:…` verb —
NOT the T3 `eval` RCE channel (which the SKILL.md edit carves out as a named proven-effect exception
to the `command id=` default-T3 rule); and a stdlib wrapper `scripts/obsidian_selection.py`
(entrypoint `bin/obsidian-selection`, sibling of `obsidian_active_note.py`: `read`/`apply`,
`--format json|path|tsv`, typed exits 0–9, CWD→vault auto-detect, **never emits `eval`**,
plugin-absent ⇒ exit 9). Write-back is guarded by live-`getCursor` optimistic concurrency
(`getRange===expect` refuses a moved/edited selection), base64 for the untrusted TEXT, a nonce that
defeats the read-back race, and coherence as a Decision-17 marker. Evals E-27/E-28 (eval-injection
refusal + second-`code=` attacker) extend the never-relax set. Full VDD pipeline + 4-lens adversarial
review (converged) + a live dogfood on `ObsidianNotes-Test` that showed the callback fires and
closed the delivery/discoverability gap (launcher + auto-detect + description triggers). See
`docs/tasks/task-068-*.md`, ARCHITECTURE §2.2.2.
**TASK 068 follow-ups (v1.3, 2026-07-16)** — a second dogfood + `/vdd-adversarial` on the plugin,
both of which found real defects:
- ⚠️ **The v1.2 "OQ1 proved" claim was WRONG-CONTEXT** (corrected here): it was checked from an
  EXTERNAL shell, where the note stays Obsidian's active leaf. In Obsidian's **integrated
  terminal** — the scenario the feature exists for — that terminal IS the active leaf, so
  `app.workspace.activeEditor` is **null** and every command returned `no-editor`. Fixed: the
  plugin remembers the last markdown editor (`active-leaf-change`/`onLayoutReady`, invalidated by
  an identity check when its leaf detaches) and resolves through it, tagging `source:
  "active"|"recent-editor"` — the same `recent-open` lesson `obsidian_active_note` already carried.
- `copy-selection-ref` (human hotkey → clipboard `@path#L…` + the **exact** selected text; a line
  ref alone is line-granular and an Obsidian paragraph is ONE source line) + a CM6 extension that
  keeps the selection highlighted while unfocused (CM6 **deletes** its selection layer on blur, so
  a CSS snippet was tried and deleted — there is no element left to style).
- ★ **Adversarial headline: `obsidian.d.ts` FABRICATED `save()` on `MarkdownFileInfo`** (the real
  interface is `{app, file, editor?}`; `save()` comes from `TextFileView` via `MarkdownView`). So
  `tsc` — the whole point of vendoring types — validated the code against a **fiction**, and the
  call could `TypeError` *after* `replaceRange` mutated the buffer. **Hand-vendored types are a
  mirror, not a gate: copy the real declarations and narrow the code to fit — never the reverse.**
  Fixed + proven by a negative control (drop the narrowing ⇒ `tsc` fails).
- `apply` now pins the **position** (GUARD 2 `position-mismatch`, offsets REQUIRED) as well as the
  text — content alone let an identical string re-selected elsewhere be replaced **silently**; the
  mutate tail can no longer leave the buffer edited with no result mirrored (`save-failed`); and
  the `.obsidian/agent-*.json` exchange files (plaintext note text in a synced dir) are cleaned up.
Contract-tested in `tests/test_obsidian_selection.py` (**38 cases**).
**Residual — restated TASK 069 (the v1.3 wording was too generous):** the shipped `main.js` has **no
gate at all**. It sits outside `tsconfig`'s `include` (which covers `main.ts` only, `noEmit`), nothing
runs `tsc` automatically (no CI/pytest/script), and there is no `obsidian` package — so the
declarations checked against are hand-written. That is how the fabricated `save()` survived. ★ A
fake-based test runtime would **not** have caught it: the fake mirrors the same wrong API model the
types did. The fix is real types + a generated `main.js` + a byte-identity drift gate — tracked as
**OQ2**, scheduled as **TASK 070**, which also carries the popout-window persist fix (blocked until
the d.ts is real). Of the other carried residuals, one dissolved and one got
WORSE on inspection — see ARCHITECTURE §2.2.2's ledger. Dissolved: `export` needs no size cap
(`apply`'s 512 KiB is an **argv** guard, and `export` has no argv in its path). **Not dissolved —
real:** concurrent dispatch is fail-safe on `apply` (GUARD 1/2/3 validate against the live
selection) but **not on `read`** — the nonce is matched on `agent-result.json`, then
`agent-selection.json` is read **unchecked** (`obsidian_selection.py:390`), so a concurrent agent
can be handed another agent's note text under `ok:true`. The plugin writes a nonce into that
payload that the wrapper never compares. One-line fix → **TASK 070**.

## Подключение к Claude Code

`.claude/skills/<name>` — per-skill симлинк на `../../skills/<name>`. Создаётся вручную или скриптом:

```bash
bin/link-skill.sh <skill-name>
```

Старые legacy-скиллы из `.agent/skills/` остаются по своему адресу: `.claude/skills/<legacy-name>` → `../../.agent/skills/<legacy-name>`.

Для соответствия Gold Standard используй `python3 .agent/skills/skill-creator/scripts/init_skill.py <name> --tier <N>` (правило `CLAUDE.md` §SKILL CREATION GATE).
