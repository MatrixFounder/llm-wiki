# templates/ — agent memory

Scaffolding templates that **`wiki-init`** renders/copies into a vault (on both
`--scaffold-new` and `--register-existing`). Consumed by
`scripts/wiki_skills/wiki_init.py::_write_agent_files` + `_write_wiki_schema`; vendor→file
routing lives in `agent-files.yaml`. Everything written is **non-destructive** (an existing
target is never clobbered without `--force`).

## Files

- **`CLAUDE.md.tmpl`** — agent-instructions for a **two-tier-scaffold (Karpathy)** vault:
  `karpathy` / `flat` / `per-project`. Describes the `_sources/_concepts/_entities` tiers,
  promote/demote, the file-layer `wiki-ingest`, `[^src-<slug>]` footnote citations, and the
  per-project `Lessons/<Course>/` two-tier diagram.
- **`CLAUDE.layout.md.tmpl`** — agent-instructions for an **existing-tree** vault:
  `dev-project` / `obsidian-personal` / `cybos`. Notes are indexed **in place** — NO
  scaffold, NO promote/demote; instead it documents `.wiki/layout.yaml` + `.wiki/sync.yaml`
  tuning, the `index_db` choice, and cite-by-`slug`. Added in **TASK 025 / R-5**.
- **The selector** (`_write_agent_files`, the ONLY difference between the two): the template
  is chosen by **layout, not vendor** — `CLAUDE.layout.md.tmpl` iff
  `layout_config.is_two_tier_scaffold(layout)` is **False**, else `CLAUDE.md.tmpl`. So:
  - `karpathy` / `flat` / `per-project` (two-tier=True) → **`CLAUDE.md.tmpl`**
  - `dev-project` / `obsidian-personal` / `cybos` (two-tier=False) → **`CLAUDE.layout.md.tmpl`**
  The layout template's placeholders are a **subset** of the Karpathy one's, so the override
  keeps `.substitute` well-formed. (If a future vendor ships its own template, make this
  override layout-suffix-aware — derive `<base>.layout.md.tmpl` — per the in-code NB.)
- **`WIKI_SCHEMA.md.tmpl`** — the per-vault identity file (`vault_id`, `schema_version`,
  `language`, `layout`, optional `index_db`, `description`). Rendered by `_write_wiki_schema`.
- **`agent-files.yaml`** — vendor → `(filename, template[, settings_file, settings_template])`
  map + `default_vendors` (omitting `--vendor` writes Claude's `CLAUDE.md` only). `gemini`
  reuses `CLAUDE.md.tmpl` VERBATIM until guidance diverges (then add `GEMINI.md.tmpl`).
- **`vault.claude-settings.json`** — TASK 026: the Claude Code permissions file dropped at
  `<vault>/.claude/settings.json` so the vault stops re-confirming every `wiki-*`/safe
  command. Copied **VERBATIM** (it is JSON with a `$schema`, NOT a `string.Template`) and
  non-destructively (`settings.local.json` is never touched).
- **`page-types/*.md`** — 13 per-class note templates (frontmatter + body skeleton):
  the 7 knowledge classes `decision`/`requirement`/`risk`/`incident`/`hypothesis`/`fact`/
  `event` (TASK 031) + the 6 agent-memory classes `agent`/`tool`/`workflow`/`capability`/
  `execution`/`pattern` (TASK 034). Each carries **type-appropriate** live event-graph edge
  keys (authored one direction — inverse auto-derived; e.g. `decision` →
  `implements`/`supersedes`/`invalidated_by`/`activated_by`, `requirement` → `implemented_by`,
  `incident` → `caused_by`/`invalidates`, `agent` → `uses`/`owns`/`implements`). **`wiki-init`
  COPIES all 13 into `<vault>/.wiki/page-types/`** for existing-tree (non-two-tier) layouts
  (`cybos`/`dev-project`/`obsidian-personal`) — `_write_page_type_templates`, VERBATIM,
  per-file non-destructive, so a vault-launched agent has them locally. The Karpathy family
  gets none (concept/entity model). Validated by `tests/test_page_type_templates.py` (every
  edge key is a real authorable key) + `tests/test_wiki_init_flows.py` (copy fires / skips /
  never indexed). Full purpose table: the manual's *"Page types & relation types"* section.

## Invariants

- **Placeholder contract.** `CLAUDE*.md.tmpl` + `WIKI_SCHEMA.md.tmpl` are
  `string.Template`s — only `${vault_id}` / `${language}` / `${layout}` / `${description}`
  substitute; a stray literal `$` must be `$$`-escaped or it raises at render (per-vendor
  resilience catches it so init never crashes). `vault.claude-settings.json` is NOT a
  Template (copied byte-for-byte).
- **SYSTEM_FILES.** Every vendor `filename` here (`CLAUDE.md`, `GEMINI.md`) MUST also be in
  `scripts/wiki_index/layout.py::SYSTEM_FILES` so `wiki-reindex` + `wiki-sync` skip it — it
  is operating instructions, not vault knowledge. (Verified by the dogfood: the FS-vs-DB
  page-count delta was exactly `{CLAUDE.md, WIKI_SCHEMA.md}`.)
- **Page-types live under `.wiki/` for safety.** The copied `.wiki/page-types/*.md` carry
  `type: decision` etc. with placeholder titles — if indexed they'd be junk pages. They are
  kept out of the index by the **walker's dot-directory prune**, NOT by an `ignore` glob
  (`obsidian-personal` doesn't even list `.wiki/**`; its `.yaml`/`.db` escape only via
  `file_extensions: ['.md']`, which would NOT exclude the `.md` scaffolds — the dot-prune is
  the real guard). `tests/test_wiki_init_flows.py::test_copied_page_types_are_never_indexed`
  pins this. Do NOT move the copy target out of a dot-directory.
- **Currency.** The agent templates name the CLI surface (e.g. "16 CLIs", `wiki-graph`,
  `--as-of`, `--tag`) and feature set — keep them in lockstep when a CLI/feature ships
  (they drifted to "15 CLIs" pre-TASK-032 and were corrected post-TASK-034). They are
  copied into real user vaults, so staleness propagates.

## Tests

`tests/test_wiki_init_flows.py` exercises the vendor→template mapping + non-destructive
write (it asserts the file is COPIED, not its prose) — so content edits here are safe.
