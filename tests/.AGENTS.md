    **Three skip/vacuity rules this file learned the hard way** — see the anti-patterns below:
    (1) the skip predicate is **per-tool** (`_esbuild_present()` / `_tsc_present()`), never one

    so a shared predicate skips the *typecheck* whenever esbuild is missing: a green meaning "not
    checked"; (2) a test that calls `pytest.skip()` on itself is recorded **SKIPPED, never FAILED**,
    so the two tests pinning rule (1) must catch the skip and assert on a bool; (3) source-grep
    tests strip comments (`_code_only`) or they pin their own rationale instead of the code.
- Pytest fixtures live in `conftest.py` at the relevant level (root for shared,
  subdir for scoped).
- Each test must have a clear failure message (`assert x, "why x must hold"`).
- E2E tests use `tmp_path` for filesystem isolation; DB tests use sqlite3 over
  tmp_path-backed file (NOT `:memory:` — WAL pragma requires file).

**Anti-patterns to reject in review**

- Tests that pass by side-effect ("function ran without exception"). Always
  assert observable behavior.
- Mocked SQLite — use real sqlite3 over tmp_path. SQLite is fast enough; mocks
  hide schema mismatches.
- Shared mutable state between tests (no module-level DBs).
- Magic skip markers without rationale.

**Vacuous greens — the repo's signature failure mode (TASK 070 added four fresh instances)**

A check that *appears* to verify X while verifying Y is worse than no check: it stands behind the
bug. These are the concrete shapes, each found live, not theorised:

- **Mocking the thing you claim to pin.** `monkeypatch.setattr(mod, "build", raises)` then asserting
  `build()` raises pins the *mock*, not `check=True`. Exercise the real code against a real bad input.
- **A skip predicate wider than the tool the test needs.** One shared `toolchain_present()` makes the
  tsc gate skip when only *esbuild* is missing. Each gate gets a predicate for the tool **it** needs.
- **A test that skips itself to prove it does not skip.** `pytest` records a self-`skip()` as
  SKIPPED, never FAILED — so the violation converts the guard into a pass. Catch it, assert a bool,
  and add a negative control proving the probe can *observe* a skip at all.
- **A source-grep that greps its own comments.** Strip comments first, or the test pins the prose
  explaining the bug rather than its absence.
- **An enumeration hand-listed under a name that promises completeness.**
  `@parametrize("tool", ["a","b","c"])` named `test_every_*` checks three remembered names; derive
  the roster from the source of truth instead.
- **A criterion that cannot return its own pass value.** `grep -rc "declare module" <plugin>/ == 0`
  was unsatisfiable once `npm install` existed (72 hits in `node_modules`) — it could neither pass
  nor ever detect a regression.
- **Hashing empty output.** A determinism check that compares two runs of a command that never ran
  compares `e3b0c442…` (sha256 of "") to itself and reads as a pass.

The test for a new gate: **name the mutation that makes it RED, then execute it.** Assertions do not
count — every claim above was settled by running the mutation, and three of them were *wrong* until
that run.
- `unittest.mock.patch("scripts.wiki_skills._manifest_consumer.<symbol>")`
  when the bound name lives in `scripts.wiki_skills.wiki_extract_concepts.*`
  via module-top import. Patch the
  **importer's binding**, not the source-of-truth module. Risk R-2 in
  `docs/PLAN.md`; regression-tested by
  `test_patch_target_lock_at_skill_module` in `test_wiki_extract_concepts.py`.
- Calling out to any model-provider SDK in tests. The v3.1 skill does
  not import a model-provider SDK at all (Decision-17 — synthesis lives
  in the orchestrator). Tests must consume the strict candidates JSON
  contract directly (via canned fixtures or constructed dicts), not
  mock an SDK call. The v2 `mock.patch("provider.Client")` pattern was
  retired in bead 003-v3-11; do not reintroduce it.
