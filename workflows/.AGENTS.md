# workflows/ — источник истины для `wiki-*` workflow-файлов

Здесь лежат многошаговые workflow-сценарии — для тех `wiki-*` скиллов, у которых есть шаг
рассуждения LLM (Decision-17: детерминированный Python-плюмбинг + **один** REASON-шаг, вынесенный
в workflow; сам Python не содержит `import anthropic`). Текущие workflow:

- **`wiki-import.md`** — конвейер конструирования (fetch+convert → REASON через
  `summarizing-meetings` → заметка + `_concepts/`, ADR-007) + батч-рецепт fan-out по списку
  источников. Wrapper `wiki-import-article` — back-compat алиас.
- **`wiki-sync.md`** — батч-**драйвер** (TASK 046): `scan` классифицирует зону и делегирует каждый
  distil-источник в `wiki-import`; готовые заметки → `wiki-index-upsert`. Без инлайнового
  summarise/convert.
- **`wiki-extract-concepts.md`** — уплотнение уже проиндексированного источника в `_concepts/`.
- **`wiki-query.md`** — RAG: retrieve → цитируемый синтез → компаундящая `_queries/*` страница.
- **`wiki-verify-multi.md`** — off-by-default аудит 4 критиками.
- **`wiki-verify-eval.md`** — eval-харнесс для verify.

(Ретайр TASK 047: `wiki-enrich.md` удалён вместе с вендоренным `wiki_ingest` — путь конструирования
теперь единый через `wiki-import`.)

## Подключение (workflow ≠ скилл)

В отличие от скиллов, workflow-файл вызывается НЕ напрямую, а через тонкую wrapper-команду:

```markdown
# commands/wiki-import.md
Read and execute the workflow defined in `workflows/wiki-import.md`.

User's task context:
$ARGUMENTS
```

Две мишени симлинков (путь к workflow в wrapper — относительный от корня проекта, поэтому один и тот
же файл читается любым вендором):

1. **`commands/<name>.md`** (wrapper) → симлинк в `.claude/commands/` → slash-команда `/<name>` в Claude Code.
2. **`workflows/<name>.md`** (сам сценарий) → симлинк в `.agent/workflows/` (vendor-зеркало для не-Claude CLI).

Новый workflow = `workflows/<name>.md` + `commands/<name>.md` + оба симлинка
(`bin/link-workflow.sh` / `bin/link-command.sh`). Legacy-фреймворковые workflow (`vdd-*`, `/light`,
`/full`, …) живут в `.agent/workflows/` отдельно — их wrapper-команды ссылаются на `.agent/workflows/X.md`.
